### **Overview of the Steps to Add a New Board to QEMU**

Adding a new board to QEMU involves multiple steps. Below is a summary of the key processes followed in our project, structured logically for explanation:

---

### **1. What is a SoC?**
A **System-on-Chip (SoC)** integrates all major components of a computing system, such as the CPU, memory, I/O peripherals, and other essential controllers, into a single silicon chip. In embedded systems, the SoC is the heart of the hardware platform, providing the necessary computational and I/O capabilities tailored for specific tasks. For example:
- The **CPU** in a SoC handles the computational logic.
- Integrated **peripherals** like UARTs, timers, and memory controllers enable communication, timekeeping, and data storage.

For our project, the **S32K358 SoC** serves as the foundation for the S32K3X8EVB board. It is pre-configured with a Cortex-M7 CPU and additional peripherals like UART and timers.

---

### **2. Adding the Board to QEMU**
A **board** in QEMU represents the hardware platform that uses a SoC. Here's how we implemented it:

1. **Create a Board File:**
   - We defined a board initialization file (e.g., `s32k3x8evb.c`) in the `hw/arm/` directory.
   - The board specifies:
     - The SoC to use (e.g., `s32k358-soc`).
     - Clock configuration (e.g., system clock).
     - Loading of firmware or kernel into memory.

2. **Integrate the Board into QEMU’s Build System:**
   - Add the board file to the `hw/arm/meson.build` file to ensure it's included during compilation.

3. **Update Kconfig:**
   - We created a `Kconfig` entry for the board, specifying its dependencies (e.g., `S32K358_SOC`) and enabling it for ARM architectures.
   - This makes the board selectable during configuration.

---

### **3. Leveraging the Pre-Implemented CPU**
The **Cortex-M7 CPU** was already implemented in QEMU, so you:
- Specified the CPU type (`cortex-m7`) when initializing the SoC.
- Configured CPU-specific properties like:
  - IRQ lines (`num-irq`).
  - Priority bits (`num-prio-bits`).
  - Enabled bit-banding (`enable-bitband`).

This step required no custom implementation but ensured the CPU is correctly integrated into your board.

---

### **4. Implementing the SoC**
To define the **S32K358 SoC**, we created:
1. **A Header File (`s32k358_soc.h`):**
   - Defined the structure `S32K358State` to manage the SoC state, including peripherals and memory regions.
   - Declared base addresses and IRQ numbers for peripherals like UART and timers.

2. **A Source File (`s32k358_soc.c`):**
   - Initialized memory regions (e.g., Flash and SRAM).
   - Connected peripherals (UART and timers) to memory-mapped I/O and IRQ lines.
   - Configured the clock and ensured peripherals were mapped into the system memory.

The SoC integrates these components into a cohesive unit, representing the real hardware architecture.

---

### **5. Configuring Peripherals**
We implemented **UARTs** and **timers** (PIT):
- For **UARTs:**
  - Mapped each UART to its base address and IRQ line.
  - Used `qdev_prop_set_chr()` to connect them to the QEMU serial device for user interaction.
- For **timers:**
  - Enable the PIT module by setting the MC_ME module, in particular we set the register PRTN0_COFB1_CLKEN, at REQ44, so we can ran the timer (in progress)
  - Configure the timer prescaler in order to have a defined clock frequency (in progress)
  - Configured a timer device (PIT) to simulate timing functionality.
  - Linked its interrupt line to the ARM Cortex-M7 CPU for proper emulation.
  - Add the reference to the library #include "hw/intc/armv7m_nvic.h" in the Makefile.
  - Define the NVIC registers (ISER3, ICER3, ISPR3, ICPR0, IABR, IPR) because we need to serve IRQ number 96.
 
 
  Relationship Between IRQs and Peripherals

Peripherals use IRQs to communicate with the CPU in real time:

    Timers: Generate IRQs to signal the end of a countdown or periodic event.
        Example: A periodic interrupt timer (PIT) signals the CPU for periodic tasks, such as updating a clock or managing real-time scheduling.
    UARTs: Raise an IRQ when data is received or when a transmission buffer is ready.
        Example: When a UART receives data from a serial line, it triggers an IRQ to notify the CPU to read the data buffer.

Each peripheral is assigned:

    IRQ Lines: Unique lines connecting the peripheral to the CPU or interrupt controller.
    Interrupt Vector: A memory location in the vector table pointing to the ISR for that peripheral.

---

### **6. Editing Build Files**
To integrate the board and SoC into QEMU:
- **`meson.build`:** Listed both the board (`s32k3x8evb.c`) and SoC (`s32k358_soc.c`) in the ARM source set.
- **Kconfig:** Enabled dependencies between the board (`S32K3X8EVB`) and SoC (`S32K358_SOC`).

---

### **7. Testing the Implementation**
After completing the board and SoC setup:
1. Rebuilt QEMU with the updated configuration:
   ```bash
   ./configure --target-list=arm-softmmu
   make -j$(nproc)
   ```
2. Ran QEMU with the new board:
   ```bash
   qemu-system-arm -M s32k3x8evb -nographic
   ```

---

### **Summary**
In summary, adding the **S32K3X8EVB** board involved:
- Defining the board and its dependencies in QEMU’s build system.
- Using a pre-existing CPU model (Cortex-M7).
- Implementing the S32K358 SoC with basic peripherals (UARTs and timers).
- Testing the configuration through QEMU commands.
