### **Updated Documentation for Adding the S32K3X8EVB Board to QEMU**

### **Overview of the Steps to Add a New Board to QEMU**

This document outlines the detailed process we followed to add the **S32K3X8EVB board**, based on the **S32K358 SoC**, into QEMU. Our implementation leveraged QEMU’s modular architecture, reusing pre-existing CPU models (Cortex-M7) while defining the board, SoC, peripherals, and memory mappings required to emulate this embedded platform.

---

The **board** acts as the high-level representation of the hardware platform, which integrates the SoC and its peripherals. We followed these steps:

1. **Board Definition:**
   - Created a file `s32k3x8evb.c` under `hw/arm/`.
   
   This file defines the initialization of the S32K3X8EVB-Q289 board in QEMU, encapsulating its connection to the SoC and the configuration of key hardware components like the system clock and firmware loading. Here’s a summary of its functionality:

    Clock Initialization:
        A fixed-frequency clock (SYSCLK) is created using clock_new() and set to 48 MHz (defined by SYSCLK_FRQ), based on the S32K358 hardware specifications.
        The clock is connected to the SoC using qdev_connect_clock_in(), ensuring it serves as the primary clock source for the system.

    SoC Instantiation:
        The S32K358 SoC is instantiated using qdev_new(TYPE_S32K358_SOC).
        The SoC is added to the machine’s object hierarchy with object_property_add_child() and associated with the SYSCLK.
        sysbus_realize_and_unref() is used to finalize the creation and registration of the SoC within QEMU’s system bus.

    Firmware Loading:
        If a firmware file is specified (machine->kernel_filename), it is loaded into the system's memory using armv7m_load_kernel(). This function places the firmware into the SoC’s flash memory region (up to FLASH_SIZE).

    Board Registration:
        The board is registered in QEMU using the DEFINE_MACHINE() macro, associating the board name (s32k3x8evb) with the initialization function s32k3x8evb_machine_init.
        This function specifies the board's description (mc->desc) and valid CPU types (e.g., cortex-m7) for the board.

    Logging:
        The file uses qemu_log() to record debugging information, such as the clock frequency and the successful realization of the SoC.

- s32k358_soc.h: 
This header file (s32k358_soc.h) provides the foundational definitions and structures needed to implement and emulate the S32K358 SoC in QEMU. It encapsulates the SoC's core features, including memory regions, peripherals, and IRQ assignments.

CPU

Clock

- Created a file `s32k358_soc.c` under `hw/arm/`.

This file implements the initialization and realization of the **S32K358 SoC (System-on-Chip)** in QEMU. It handles setting up the system clock, memory regions, peripherals (such as LPUARTs and PIT), and their integration with the CPU and other components. Below is a detailed summary:

---

### **1. Purpose**
The file creates a model of the **S32K358 SoC**, enabling QEMU to simulate its hardware features. It defines initialization, configuration, and realization steps for the SoC's components, ensuring accurate emulation of memory, peripherals, and interrupts.

---

### **2. Key Functionality**
#### **Initialization (`s32k358_soc_initfn`)**
- **Purpose:** Prepares the SoC state and its subcomponents before realization.
- **Steps:**
  - Initializes the **Cortex-M7 ARMv7M CPU core** (`object_initialize_child` for `armv7m`).
  - Sets up the **PIT (Periodic Interrupt Timer)**.
  - Configures **8 LPUART instances**.
  - Creates the **system clock** (`qdev_init_clock_in`), which connects to the SoC's components.

---

#### **Realization (`s32k358_soc_realize`)**
- **Purpose:** Finalizes the SoC setup and integrates it into the QEMU emulation environment.
- **Steps:**
  1. **System Clock Validation:**
     - Ensures the `sysclk` clock is connected; an error is reported if not.
  2. **Memory Setup:**
     - Configures **Flash memory** as ROM (`memory_region_init_rom`) and adds an alias region.
     - Initializes **SRAM** as RAM (`memory_region_init_ram`).
     - Maps these memory regions into the system's memory space.
  3. **CPU Realization:**
     - Realizes the Cortex-M7 CPU (`sysbus_realize`).
     - Configures CPU properties, including:
       - 240 IRQ lines (`num-irq = 240`).
       - 4 priority bits.
       - Bit-banding enabled (`enable-bitband = true`).
     - Links the CPU's clock input (`cpuclk`) to the system clock.
  4. **LPUARTs Realization:**
     - Sets up 8 LPUART modules:
       - Connects each LPUART to a corresponding `chardev` (e.g., serial ports for UART communication).
       - Maps MMIO regions for each LPUART to incrementing base addresses (e.g., `LPUART_BASE_ADDR + i * 0x4000`).
       - Connects LPUART IRQs to the CPU's GPIO lines.
  5. **PIT Realization:**
     - Links the PIT clock (`pclk`) to the system clock.
     - Maps PIT's MMIO region to its base address (`PIT_BASE_ADDR`).
     - Connects PIT's IRQ to the CPU GPIO.

---

### **3. Integration with QEMU**
#### **Type Definition and Registration**
- Registers the SoC as a QEMU device:
  - `TYPE_S32K358_SOC` is defined as a QEMU object.
  - Specifies that the SoC is a `SYS_BUS_DEVICE`.
  - Links the initialization (`s32k358_soc_initfn`) and realization (`s32k358_soc_realize`) methods.

---

### **4. Key Components Modeled**
1. **CPU**: ARM Cortex-M7 core, configured with 240 IRQ lines, 4 priority bits, and bit-banding enabled.
2. **Peripherals**:
   - **PIT**: Configures the periodic interrupt timer and links it to the system clock and CPU.
   - **LPUARTs**: Realizes 8 UART modules, connects them to serial devices, and maps MMIO and interrupts.
3. **Memory**:
   - **Flash**: Defined as ROM with an alias region for memory remapping.
   - **SRAM**: Allocated and mapped into system memory.

### **5. Configuring Peripherals**

Peripheral implementation focused on **UARTs** and **timers**, with an emphasis on correct memory mapping and IRQ handling:

### **Overview of the `s32k358_lpuart` Module**

The `s32k358_lpuart.c` and `s32k358_lpuart.h` files in QEMU model the **Low Power Universal Asynchronous Receiver-Transmitter (LPUART)** for the **S32K358 SoC**. The module enables serial communication between the emulated system and external devices, making it integral to interacting with QEMU for applications requiring UART-based communication. The implementation covers the initialization, memory-mapped I/O, register operations, and IRQ handling for each UART module.

---

### **Key Components**

#### **LPUART Registers**
The LPUART module's functionality is controlled through several key registers, as defined in `s32k358_lpuart.h`:
- **Baud Rate Register** (`LPUART_BAUD`): Controls the UART's baud rate.
- **Status Register** (`LPUART_STAT`): Holds status flags like `TDRE` (Transmit Data Register Empty) and `RDRF` (Receive Data Register Full).
- **Control Register** (`LPUART_CTRL`): Enables or disables the transmitter (`TE`) and receiver (`RE`).
- **Data Register** (`LPUART_DATA`): Holds data being transmitted or received.

#### **State Structure**
The `S32K358LPUARTState` structure, defined in `s32k358_lpuart.h`, encapsulates the following components:
- **MMIO region**: Memory-mapped I/O for communication with the LPUART.
- **IRQ line**: Represents the interrupt line for the UART.
- **Baud rate, status, control, and data registers**: Store the UART’s operational state.
- **Character backend (`chr`)**: Manages the UART communication.

#### **Key Functions**

1. **`s32k358_lpuart_init`**:
   - Initializes the UART device by setting up its MMIO region and IRQ line (`sysbus_init_irq`, `memory_region_init_io`).
   - This function configures the system to handle UART operations and communication.

2. **`s32k358_lpuart_realize`**:
   - Finalizes the configuration of the LPUART by setting default values for its registers (baud rate, control, etc.).
   - Sets up the UART's receive and transmit handlers (`qemu_chr_fe_set_handlers`), enabling communication between the device and external systems.

3. **`s32k358_lpuart_read` and `s32k358_lpuart_write`**:
   - **`s32k358_lpuart_read`**: Reads the LPUART registers (baud, status, control, and data).
   - **`s32k358_lpuart_write`**: Writes to the LPUART registers, updating control, baud rate, or data values.
   - These functions enable interaction with the emulated LPUART hardware through memory-mapped I/O.

4. **`s32k358_lpuart_can_receive` and `s32k358_lpuart_receive`**:
   - **`s32k358_lpuart_can_receive`**: Checks if data can be received by verifying the receiver flag (`RDRF`).
   - **`s32k358_lpuart_receive`**: Handles the reception of data by updating the data register and setting the receive flag (`RDRF`), triggering an interrupt via `qemu_set_irq`.

---

### **Memory-Mapped I/O and IRQ Handling**
The LPUART registers are mapped to specific memory offsets, and the LPUART is linked to IRQ lines for interrupt-driven communication:
- **MMIO Setup**: The LPUART's MMIO region is mapped to an address (e.g., 0x20 for each UART) for direct register access via the system’s memory. This allows reading and writing UART data to and from memory.
- **IRQ Handling**: When the LPUART triggers an interrupt (e.g., after data is received or transmitted), an IRQ is signaled to the CPU. The `qemu_set_irq` function is used to propagate the interrupt and notify the CPU.

---

### **Initialization and Integration with the System**
- The **UART initialization** involves setting up the MMIO region, IRQs, and the character backend interface for UART communication.
- The **realization process** configures the UART hardware, prepares the device to interact with the CPU, and ensures the device is properly registered in the QEMU system.
- The **IRQ setup** ensures the LPUART can communicate with the CPU when an event (e.g., data received) occurs, triggering appropriate interrupt service routines (ISRs).

---

### **Logging and Debugging**
Throughout the module, `qemu_log` and custom debug macros are used for logging UART operations, helping track the initialization process, interrupt handling, and I/O operations. This aids in debugging the UART behavior when interacting with QEMU.

### **Overview of the `s32k358_pit` Module**

The **S32K358 Periodic Interrupt Timer (PIT)** is a crucial peripheral in the **S32K358 SoC**, providing periodic interrupts to the CPU for time-based operations, such as periodic events or task scheduling. The `s32k358_pit.c` and `s32k358_pit.h` files in QEMU emulate the PIT device, managing its configuration, timer functionality, and interrupt handling.

---

### **Key Components**

#### **PIT Registers**
The PIT device's functionality is controlled through several key registers, defined in `s32k358_pit.h`:
- **Module Control Register** (`PIT_MCR`): Controls the PIT's global enable and freeze functionalities.
- **Timer Load Value Register** (`PIT_LDVAL0`): Specifies the timer's initial load value, defining the timer period.
- **Current Timer Value Register** (`PIT_CVAL0`): Holds the current value of the timer.
- **Timer Control Register** (`PIT_TCTRL0`): Manages the timer's enable (`TEN`) and interrupt enable (`TIE`) bits.
- **Timer Flag Register** (`PIT_TFLG0`): Indicates when the timer has expired and triggered an interrupt.

#### **State Structure**
The `S32K358PITState` structure defines the state of the PIT, which includes:
- **Memory-mapped I/O** (`iomem`): Used for communication with the PIT registers.
- **IRQ line** (`irq`): Connected to the CPU’s interrupt controller for signaling PIT interrupts.
- **Clock and Timer**: Manages the PIT’s clock (`pclk`) and timer state (`timer`), which is initialized by the `ptimer` framework.

#### **Key Functions**

1. **`s32k358_pit_init`**:
   - **Purpose**: Initializes the PIT device by setting up memory-mapped I/O and IRQ lines. The PIT is configured with its `pclk` (clock) and interrupt handling.
   - **Actions**: Creates the memory region for the PIT (`memory_region_init_io`), initializes the IRQ line (`sysbus_init_irq`), and sets the PIT clock using `qdev_init_clock_in`.

2. **`s32k358_pit_realize`**:
   - **Purpose**: Finalizes the configuration of the PIT. Ensures that the clock (`pclk`) is connected, initializes the timer (`ptimer_init`), and configures the interrupt behavior.
   - **Actions**: Sets the timer period from the clock and initializes the timer with specific flags to control its behavior (e.g., wrap after one period, no immediate reload). It then commits the timer configuration with `ptimer_transaction_commit`.

3. **`s32k358_pit_read` and `s32k358_pit_write`**:
   - **Purpose**: These functions handle read and write operations for the PIT's memory-mapped registers.
   - **Actions**:
     - **`s32k358_pit_read`**: Reads the values of PIT registers (e.g., `MCR`, `LDVAL0`, `CVAL0`, `TCTRL0`, `TFLG0`) based on the requested memory offset.
     - **`s32k358_pit_write`**: Writes values to the PIT registers, such as setting the load value (`LDVAL0`), controlling the timer (`TCTRL0`), and clearing the interrupt flag (`TFLG0`).

4. **`s32k358_pit_tick`**:
   - **Purpose**: The callback function that is triggered when the PIT timer reaches zero, signaling an interrupt.
   - **Actions**: Checks if the interrupt flag (`TIE`) is enabled. If so, it sets the interrupt flag (`TFLG0`) and triggers the IRQ line (`qemu_irq_pulse`), notifying the CPU of the interrupt.

5. **`s32k358_pit_clk_update`**:
   - **Purpose**: Updates the PIT's timer period based on the system clock (`pclk`).
   - **Actions**: Updates the period of the timer by recalculating it based on the current system clock frequency (`ptimer_set_period_from_clock`).

---

### **Memory-Mapped I/O and IRQ Handling**
- **Memory Mapping**: The PIT registers are mapped to specific memory offsets, allowing the CPU to interact with them via memory accesses. This enables reads and writes to control the PIT timer, load values, and status flags.
- **IRQ Handling**: The PIT can generate interrupts when the timer expires. The `qemu_irq_pulse` function triggers the interrupt, which is then processed by the interrupt controller. The PIT’s interrupt line is linked to IRQ line 96, which is handled by the NVIC (Nested Vectored Interrupt Controller) in the ARM Cortex-M7 CPU.

---

### **Clock Management**
- The PIT is clocked by the `pclk` (periodic clock), which is connected via `qdev_init_clock_in`. This clock controls the timer’s tick rate.
- The clock update function (`s32k358_pit_clk_update`) ensures that the timer’s period is adjusted according to the clock frequency, enabling accurate timing for periodic events.

---

### **Initialization and System Integration**
- The PIT device is initialized in the **S32K358 SoC** through `s32k358_soc_initfn`, where it is instantiated and added to the system bus (`object_initialize_child`). The system clock (`sysclk`) is passed to the PIT to drive its timing functionality.
- The **realization** of the PIT is handled in `s32k358_pit_realize`, where it is connected to memory regions and IRQ lines, and its clock is set up.

---

### **Logging and Debugging**
Debugging and logging mechanisms are provided in the module using `qemu_log` and debug macros. These logs help track the PIT’s state and behavior, particularly useful for ensuring the timer operates correctly and the interrupts are triggered as expected.
